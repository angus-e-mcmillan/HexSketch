# LLM benchmark

How much better does a model answer chemistry questions with HexSketch's
tools than without them? Each question is asked through OpenRouter in up to
three conditions, and the final answers are graded automatically.

| Condition | The model has |
|---|---|
| `blind` | No tools |
| `readback` | `validate_structure` only: HexSketch reads back the name and formula of a SMILES it wrote |
| `full` | Every checking tool the connector has (`validate`, `name`, `analyze`, `compare`, `convert`) |

The tool descriptions and input schemas are the connector's own (imported
from `packages/hexsketch/src/toolkit.ts`), and the tools run in-process, so
no server is involved. `render_structure` is left out because it returns a
picture, and results omit the hexsketch.com link.

## Questions

`questions.jsonl` is built by `prep.ts` and committed. The pilot is 30
questions; the full set is 132.

| Category | Asks | Graded |
|---|---|---|
| `name2smiles` | The SMILES for an IUPAC name | Same compound |
| `stereo` | The same, for names with R/S or E/Z | Same stereoisomer |
| `smiles2name` | The IUPAC name for a SMILES | OPSIN parses the name; same compound (or stereoisomer) |
| `formula` | The molecular formula for a name | Element by element |
| `reaction` | The product of a textbook reaction | Same compound |

The names and structures come from the ZINC sets in the naming benchmark
(`tools/bench/structures.tsv`, charged protonation states left out). Every
name was generated by HexSketch and parsed back to the same structure by
OPSIN. The reactions were written by hand. Rebuild with
`node --experimental-strip-types tools/llm-bench/prep.ts` (needs Java); it
gives the same file every time.

**Bias to note:** the names are in HexSketch's own style. With tools, a model
can name its SMILES with `name_structure` and compare the two names directly.
That is a real use of the tool, but before publishing, consider adding names
from an independent source (PubChem's IUPAC names) for comparison.

## The hard set

`hard.jsonl` (`--set hard`) is 65 questions picked by hand because models get
them wrong, asked in a mix of IUPAC names, trivial names and SMILES. The list,
with the trap in each, is in `hard.ts`. The pilot is 33 of them.

| Category | Asks | Examples |
|---|---|---|
| `name2smiles` | SMILES for a hard IUPAC name | von Baeyer and spiro names, fusion locants (thieno[3,2-c]pyridine), indicated hydrogen, `2,5,8,11-tetraoxadodecane` |
| `smiles2name` | IUPAC name for a SMILES | fused heterocycles, spiro ketals, (2Z,4E) dienes, (1R,4R)-camphor |
| `common2smiles` | SMILES with every stereocentre for a trivial name | strychnine, morphine, paclitaxel, erythromycin A, sucrose |
| `common2name` | Systematic name with R/S for a trivial name | L-cysteine (R, unlike the other amino acids), L-threonine, (−)-menthol |
| `formula` | Formula of a large natural product | vancomycin, cyclosporin A, vitamin B12 |
| `smiles2formula` | Formula of a long, unnamed SMILES | ritonavir, venetoclax, digoxin |
| `reaction` | Product where the obvious answer is wrong | SN2 and Mitsunobu inversion, meso products, Hofmann elimination, Baeyer–Villiger, Favorskii |

Every key is checked two ways by `prep-hard.ts`: each IUPAC name must parse
(OPSIN) to the SMILES written beside it, and each trivial-name compound is
PubChem's (CID recorded), with HexSketch's formula equal to PubChem's.
`--pubchem` re-fetches them all from PubChem to check again. A trivial name
in a `common2name` answer is marked wrong, since OPSIN would parse it too.

```sh
node --experimental-strip-types tools/llm-bench/prep-hard.ts --pubchem
```

## The exam bank

The HexSketch Exam Bank page (https://claude.ai/artifact/GACFCceuef8rxnNUTuVQgu)
is where questions are written and reviewed. Each question has its prompt (shown
as the model receives it), its key (a structure, the compound to be named, or a
formula), answers that also earn the mark, whether stereochemistry is marked,
and an examiner's note that is never sent to the model. HexSketch draws, names
and checks each key as it is typed; a key can be pasted as SMILES, a
hexsketch.com link or a structure copied with Edit › Copy for AI.

Claude exports the bank into `bank/questions/` (one file per question, committed),
and `prep-bank.ts` turns the questions marked Ready into `exam.jsonl`:

```sh
node --experimental-strip-types tools/llm-bench/prep-bank.ts
npm run llm-bench -- --model anthropic/claude-opus-5 --set exam --repeats 1
```

The page's code is `bank/index.html`; it loads HexSketch from `hexsketch.js`,
built with `npm run llm-bench:bank`.

## Running it

Once:

```sh
sh tools/opsin/fetch.sh
```

Then put your OpenRouter key in `tools/llm-bench/.env`. Git ignores this
file, so never paste the key anywhere else:

```
OPENROUTER_API_KEY=sk-or-...
```

Find a model's exact id and price:

```sh
npm run llm-bench -- --list-models opus
```

Run the pilot (with no `--all`, only the 30 pilot questions run):

```sh
npm run llm-bench -- --model anthropic/claude-opus-5 --provider anthropic --conditions blind,full --repeats 1
```

| Option | Default | |
|---|---|---|
| `--model` | required | OpenRouter model id, recorded with each answer |
| `--provider` | any | Pin one provider, with no fallbacks (e.g. `anthropic`) |
| `--conditions` | `blind,full` | Any of `blind`, `readback`, `full` |
| `--repeats` | 3 | Passes through the questions; the report shows their range |
| `--set` | `standard` | `standard` (questions.jsonl), `hard` (hard.jsonl) or `exam` (exam.jsonl, from the exam bank) |
| `--all` | off | The whole set rather than its pilot |
| `--only` | | Comma-separated question ids |
| `--effort` | `medium` | `reasoning.effort`; `none` for a model without thinking |
| `--max-tokens` | 32000 | The same for every model, so thinking budgets match |
| `--max-rounds` | 10 | Tool rounds before the model must answer |
| `--concurrency` | 4 | Questions in flight at once |
| `--run` | date-model | Name of the run; give an old one to carry on where it stopped |
| `--dry-run` | | Show how many requests it would make, then stop |

Every request sets `require_parameters: true`, so a provider that would
quietly ignore the effort setting or the tools is never used. The temperature
is left at each model's default (Claude with thinking requires that), and the
repeats show how much the answers vary.

## Output

- `results/<run>.md` and `results/<run>.json`: the summary. Commit these. It
  has accuracy per condition and category, cost, tokens (thinking separately),
  median time and tool calls per question, plus the exact model and provider
  that answered, the settings, the commit and the question set's hash.
- `out/<run>/`: every transcript and graded record. Not committed.

To test the runner without spending anything, run a stand-in for OpenRouter:

```sh
node --experimental-strip-types tools/llm-bench/test/mock.ts 8788 &
LLM_BENCH_API=http://localhost:8788 OPENROUTER_API_KEY=test npm run llm-bench -- --model mock/model --repeats 1 --run mock
```
